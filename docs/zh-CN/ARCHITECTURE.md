# 架构

[English](../ARCHITECTURE.md) | [中文文档索引](README.md)

AssumeZero 由一个 Rust 库和一个轻量 CLI 二进制组成。主要模块如下：

- `cli`：命令选择、配置优先级、诊断和退出码映射；
- `config`：严格、带版本的 TOML 解析与校验；
- `engine`：基线门禁、场景编排、恢复实验、预算和证据等级；
- `workspace`：每次运行的工作区副本、大小限制、排除规则、Git-clean 模式和符号链接策略；
- `runner`：直接创建进程、有界 stdout/stderr 捕获、超时和 best-effort 中断；
- `oracle`：确定性的运行接受条件；
- `scenarios`：稳定 ID 和能感知平台能力的环境/路径方案；
- `minimize`：预算感知的 `ddmin` 与显式 1-minimal 验证；
- `redaction`：内存中的精确值/模式脱敏和路径替换；
- `report`：终端、JSON、Markdown 和 JUnit 输出；
- `fingerprint`：源文件内容和 Git 状态的完整性证据；
- `platform`：命令查找、路径处理、必要环境变量和平台事实。

## 执行流程

1. 解析并校验配置，拒绝未知字段。
2. 选择命令，`--` 后的 Token 优先。
3. 在改变任何 `PATH` 之前解析顶层可执行文件。
4. 为源文件生成指纹并记录 Git 状态。
5. 在彼此独立的副本中运行基线。
6. 除非所有基线运行均满足 Oracle，否则停止归因。
7. 在新副本中运行每个选中的场景。
8. 重复确认改变条件后的失败。
9. 对支持的场景恢复并 1-minimize 名称或有序条目。
10. 再次生成并比较源状态指纹。
11. 在内存中脱敏，然后写出报告 Schema v1。

进程运行器接收可执行文件和参数向量，不会拼接 Shell 字符串。显式使用 `--shell` 时，只有在显示安全警告后，才会把用户脚本转换为对应平台的 Shell 参数。

## 跨平台设计

平台专属代码通过编译期分支隔离。Windows 会保留必需的进程变量并识别 `PATHEXT`、`.cmd` 和 `.bat`；Unix 会检查可执行位。路径列表使用宿主平台分隔符并保持顺序。不支持的 Locale/时区能力会明确跳过，而不会被视为通过。
